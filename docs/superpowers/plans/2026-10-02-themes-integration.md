# Themes Integration Plan

> **For the orchestrator** (not for the theme agents): run this after the groundwork (`2026-10-02-themes-groundwork.md`) and the three theme plans (`…-theme-mare-alta.md`, `…-theme-chateau-royal.md`, `…-theme-cabo-verde.md`) have each reported. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Bring the three finished themes together: the home page lists them, the whole repo is green, the user reviews the new UI, the vault is up to date. Nothing is committed.

**Architecture:** The three agents only touched their own folders and catalogue namespaces. Integration is what they were not allowed to do: the shared home list, a repo-wide verification, the covers, the documentation, and the review with the user.

**Spec:** `docs/superpowers/specs/2026-10-02-three-themes-design.md` (D11, *Verification*, *Out of scope*).

## Global Constraints

- Never commit or push; never `db push`. At the end, ask the user for the go.
- Discussion in French; code, comments and vault notes' code in English; vault notes in French as the vault is.
- The orchestrator edits only: `landing/src/components/home/themes.ts`, the three `public/themes/<id>/cover.webp`, the vault, `themes/README.md`'s stale "Known debt" lines. Anything else wrong is sent back to the owning agent.

## Review Focus

- A theme the home list names but whose cover is missing shows a broken image on the marketing page (Task 2).
- `shared/data/theme-modules.ts` is regenerated by `themes:sync`; `shared/lib/addable-modules.test.mjs` pins ciao-amore's exact module list and must still pass (Task 1).
- Three themes' CSS now load in the same document: a leaked global rule or a shared keyframe name shows only here, in the editor's preview or the home page (Task 1, step 4).
- The Jour J blocks of Maré Alta link to a French, unthemed page; that is known and recorded, not a defect to fix here (Task 4).
